# Poster Forge

## Design Context

### Users

An internal team (often a single operator) producing game posters in batches, every day. They arrive with a folder of provider artwork and leave with exported PNG/WebP files. Speed and repeatability matter more than onboarding: the same person runs the same ten adjustments dozens of times per session, on a desktop screen, usually 1440px wide or more.

The job to be done is judgement, not data entry. Every control exists to answer one question — does the poster look right? — so the poster itself has to be the largest, brightest, most stable thing on screen, and the controls have to stay within reach without competing for attention.

### Brand Personality

Compact, mechanical, unfussy. A control desk, not a landing page. The interface should feel like equipment: dense, predictable, quiet until you touch it. No marketing voice, no decorative reassurance, no explaining what the user already sees.

### Aesthetic Direction

A canvas-first workspace: a slim top bar, two scrolling side rails, and the poster centred in an uncluttered stage that grows to fill the available height. Surfaces are flat and separated by hairlines rather than floating cards with shadows — the only elevated object is the poster, because it is the artefact.

Both themes ship. Dark is the default because judging poster colour requires a neutral dark surround; light exists for bright rooms. Neutrals are tinted toward the amber brand hue so both themes read as the same product. Amber is the single accent and stays rare — primary actions and active states only.

References: Lightroom's develop module and Figma's inspector for the rail/stage/rail proportions and control density. Anti-references: the previous version's oversized Impact headline, glassmorphism panels, and every-button-is-amber hierarchy.

Type pairs Anton (already loaded for poster rendering, so it costs nothing) as the wordmark with Archivo for interface text — a neutral grotesque with tabular figures for the many numeric readouts.

### Design Principles

1. **The poster is the hero.** It sizes to the available height and never yields space to chrome. If a decision doesn't make the poster easier to judge, it doesn't belong on screen.
2. **Fill the frame.** No dead gutters, no columns that cap out below their container. The stage absorbs whatever width the rails don't need.
3. **Equal panes, independent scroll.** Rails are full height and scroll internally, so adding controls never stretches the page or leaves a stub column.
4. **Density is a feature.** 36px controls, 12px rhythm, one accordion section open at a time. Tight within a group, generous between groups.
5. **Earn every pixel of ink.** Three levels of button, one accent colour, no text that restates what the interface already shows.


### Title controls

Use one Game font selector. The former Title style selector was removed because its
font, skew, colours and layout competed with the font override. A shared upright
layout now keeps those choices predictable; size, outline, spacing and curve stay
in the tuning panel. Existing cached style/font pairs migrate to their effective
font. Font families already available in the editor remain selectable.


New posters default to proportional title fitting so letters keep their shape.
Existing saved posters retain the previous horizontal width fit, which preserves
requested letter height. Both modes reserve curve, outline and shadow clearance.
Line breaks remain stable while adjusting size; the operator can insert / or use
Suggest line breaks. The title safe-width guide is an editor overlay, never part
of exported artwork. Keep all existing per-line sizes, spacing and curve controls.

### Reusable production workflow

Font browsing groups the existing faces and previews the current game name; all
selection paths update the single Game font field. Favourites are browser-local.
Image palette suggestions require an explicit click. Batch per-image colour is
opt-in, and must respect protected edited/approved drafts.

Full layout templates fill existing controls rather than introducing a competing
Title style. They preserve current artwork, title, filename and image transforms.
Batch status filters and source comparison are review tools, not new settings.

Batch drafts and templates use IndexedDB on the current site/browser. Store image
blobs, settings, source transforms, logos and backdrop media, not only record IDs.
Persist current edits after a pause; show save failures and retain an unload guard
while changes are pending. Restore source order and selection. Do not imply cloud
synchronisation or persistence of the complete undo history across a refresh.
